# ADR-0001：采用模块化单体与事务 Outbox

## 状态

已接受。

## 背景

项目需要验证异步处理、状态机、幂等、重试、审核和审计，但当前目标是可运行的求职展示级 MVP，而不是建设多团队微服务系统。

## 决策

- API、Worker 和 Scheduler 使用同一个 Python 代码库和镜像。
- PostgreSQL 保存业务状态，Redis 仅负责 Celery Broker 和 SSE Pub/Sub。
- 任务创建与 Outbox 事件在一个数据库事务中提交。
- Worker 通过执行记录和租约实现至少一次消费下的幂等效果。

## 结果

优点是部署简单、事务边界清晰、可以完整演示可靠性设计。代价是数据库和代码仓库仍是单点演进单元；未来按任务、审核、通知拆分服务时，应保留事件 schema 版本并引入独立消费者组。
